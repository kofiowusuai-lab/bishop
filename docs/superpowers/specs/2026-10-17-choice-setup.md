# Choice-driven provider setup

The user's screenshots and instruction authorize replacing normal free-text configuration with menus. Normal setup: provider -> optional OpenCode plan -> existing/new profile choice -> Keep/Replace/Clear credential choice -> live model catalog -> searchable model picker -> save. New profiles get deterministic names automatically; no profile-name or model-ID prompt. Secrets remain private typed entry. A custom endpoint remains explicit advanced input, never required for presets.

Use current provider catalogs, not copied screenshot model names. OpenRouter models filter tool capability when advertised. Local models list installed models. Anthropic models use native catalog headers. OpenCode plans route to their documented endpoints and use Bishop identification/session headers; unsupported native protocols are excluded or explicitly routed rather than pretending all models share chat-completions. Free means models currently labeled free in the provider catalog, not a guarantee of future price/access. If a catalog fails, show Retry, existing model if any, or Back/Cancel; never force a guessed manual model entry or silently paid fallback.

Searchable picker is height-bounded, paginated/scrollable and shows current selection, with arrows, Enter, Esc/back and type-to-search. Non-TTY tests can choose IDs/numbers. Key action must preserve endpoint binding; Clear removes saved credential only, never environment variables (explain overrides). Cancelling setup must preserve existing profile/credential; stage edits until model confirmed. Changing an existing provider/model is menu-driven in /model and setup. No credentials from Hermes imported. Live setup performs catalog GET only, no inference.

Scope: existing adapters and supported providers, OpenCode Zen/Go/Free for supported protocols. Do not copy an unverified list of every provider in another app. Test menus with actual PTY, fake catalogs and failure/cancel paths. Publish verified patch using existing user authorization to ship Bishop live.
